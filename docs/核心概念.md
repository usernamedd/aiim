## 一、产品概述

### 1.1 什么是 AIIM

**AIIM**（AI-墨）是一款多端 AI 聊天工具，支持桌面端和移动端，涵盖两个行业切面：

| 切面 | 定位 | 核心功能 |
|------|------|---------|
| **金融研究** | 投资研究与分析 | K线图、持仓管理、实时行情监控 |
| **软件工程** | 程序员协作与开发 | 文件浏览器、代码编辑、调试控制台、AI助手 |
| **通用** | 基础 IM | 私聊、群聊、联系人管理 |

### 1.2 目标用户

- **金融从业者**：分析师、基金经理、散户投资者
- **软件工程师**：开发者、架构师、DevOps
- **通用用户**：日常社交与协作

### 1.3 核心价值

- **多端一致**：桌面 + Android + iOS 三端体验统一
- **AI 驱动**：结合 AI 能力提升行业特定场景效率
- **可扩展**：六边形架构保障业务快速迭代

## 二、技术架构

### 2.1 三端技术栈

```
┌─────────────────────────────────────────────────────────┐
│                     AIIM 全端架构                          │
├──────────────┬──────────────┬──────────────────────────┤
│   桌面端      │   Android    │          iOS             │
│   Tauri      │   Kotlin     │          Swift            │
│   React      │   Compose    │          SwiftUI         │
│   TypeScript │   Kotlin     │          Swift           │
├──────────────┴──────────────┴──────────────────────────┤
│                    共享业务逻辑层                          │
│           (Domain / Use Cases / Ports)                   │
├──────────────────────────────────────────────────────────┤
│                      后端服务层                            │
│        Go + Gin + GORM + JWT + WebSocket                 │
│                 SQLite / MySQL 数据库                      │
└─────────────────────────────────────────────────────────┘
```

### 2.2 桌面端架构（Hexagonal）

```
┌──────────────────────────────────────────────────────────────┐
│                        UI Layer                              │
│          React 组件: pages / components / hooks             │
└─────────────────────────────┬────────────────────────────────┘
                              │ 调用
┌─────────────────────────────▼────────────────────────────────┐
│                   Adapters Layer（驱动适配器）                   │
│              driving/tauri/ ← Tauri Commands                 │
└─────────────────────────────┬────────────────────────────────┘
                              │ 调用
┌─────────────────────────────▼────────────────────────────────┐
│                   Application Layer                           │
│         Use Cases：用例编排，调用 Domain                       │
│         ports/driving/ ← 输入端口（UI 调用的服务接口）          │
│         ports/driven/  ← 输出端口（Repository/Gateway 定义）   │
└─────────────────────────────┬────────────────────────────────┘
                              │ 调用
┌─────────────────────────────▼────────────────────────────────┐
│                    Domain Layer ★                             │
│            纯业务逻辑，无任何外部依赖                            │
│   entities/     ← 核心实体（User/Message/ChatRoom/Contact）    │
│   value-objects/← 值对象（MessageId/Token/Credentials）        │
│   services/     ← 领域服务（纯函数）                           │
│   events/       ← 领域事件（MessageSent/UserLoggedIn）         │
└─────────────────────────────┬────────────────────────────────┘
                              │ 实现
┌─────────────────────────────▼────────────────────────────────┐
│                   Adapters Layer（从驱动适配器）                 │
│    driven/api/       ← REST API 适配器（Axios）                │
│    driven/websocket/ ← WebSocket 适配器                       │
│    driven/storage/   ← localStorage 适配器                    │
│    driven/repository/← Repository 实现                        │
└──────────────────────────────────────────────────────────────┘
```

**依赖方向：严格单向**

```
UI → adapters(driving) → application(use-cases) → domain
                                              ↓
                                    adapters(driven) → 外部世界
```

### 2.3 移动端架构

**Android**：Kotlin + Jetpack Compose + MVVM + Kotlin Coroutines/Flow

```
presentation/     ← UI + ViewModel
    ├── ui/      ← Compose 页面
    └── viewmodel/
domain/           ← 业务逻辑（无外部依赖）
    ├── model/
    ├── usecase/
    └── repository/  ← Port 接口
data/             ← Repository 实现
    ├── api/
    └── repository/
infrastructure/   ← DI / Storage
```

**iOS**：Swift + SwiftUI + MVVM + Combine/async-await

```
Presentation/     ← SwiftUI Views + ViewModels
Domain/           ← Entities + Ports + UseCases
Application/      ← Adapters + Services
Infrastructure/   ← Network + Storage
```

### 2.4 后端架构

Go + Gin Web 框架，六边形风格：

```
adapters/inbound/http/   ← HTTP Handlers (Gin)
adapters/inbound/ws/     ← WebSocket Handler
adapters/outbound/      ← 外部依赖适配器
    ├── persistence/    ← GORM 数据库
    ├── token/           ← JWT 服务
    └── realtime/        ← WebSocket Hub
domain/model/            ← 核心实体
domain/service/          ← 领域服务
domain/errors/           ← 业务错误定义
ports/inbound/           ← 输入端口接口
ports/outbound/          ← 输出端口接口
```

## 三、业务概念

### 3.1 认证体系

| 概念 | 说明 |
|------|------|
| **User** | 用户实体，含 username/email/nickname/avatar/status |
| **Token** | JWT 访问令牌 + RefreshToken 双令牌机制 |
| **Session** | 用户会话，支持多设备登录管理 |
| **AuthFlow** | 登录 → 注册 → 忘记密码 → 重置密码 |

**API 端点：**

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/auth/register` | 注册 |
| POST | `/api/v1/auth/login` | 登录 |
| POST | `/api/v1/auth/refresh` | 刷新 Token |
| POST | `/api/v1/auth/logout` | 登出 |

### 3.2 聊天体系

| 概念 | 说明 |
|------|------|
| **ChatRoom** | 聊天室，含私聊/群聊两种类型 |
| **Message** | 消息实体，含文本/图片/文件/代码块类型 |
| **Contact** | 联系人，含 username/nickname/avatar/isOnline |
| **Group** | 群组实体，含 name/avatar/memberIds |

**消息状态：**

- `sending` → `sent` → `delivered` → `read`
- 未读计数（unreadCount）

**API 端点：**

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/chats` | 最近会话列表 |
| GET | `/api/v1/chats/:chat_id/messages` | 消息历史（分页） |
| POST | `/api/v1/chats/direct` | 创建私聊 |
| POST | `/api/v1/chats/group` | 创建群聊 |
| WS | `/ws` | WebSocket 实时消息 |

### 3.3 行业切面

**AppMode 枚举：**

```typescript
type AppMode = 'finance' | 'software' | 'general'
```

| 切面 | 页面 | 功能 |
|------|------|------|
| `finance` | P40 仪表盘 / P41 持仓详情 | K线图、持仓管理、实时行情 |
| `software` | P30 文件浏览器 / P31 调试控制台 / P32 差异对比 / P33 AI助手 | 文件树、代码编辑、调试、差异对比 |
| `general` | — | 基础 IM 功能 |

## 五、API 设计

### 5.1 响应格式

**成功响应：**

```json
{
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

**错误响应：**

```json
{
  "code": 401,
  "message": "error description"
}
```

### 5.2 认证方式

- 请求头：`Authorization: Bearer <access_token>`
- 访问令牌有效期：1 小时
- 刷新令牌有效期：7 天

### 5.3 WebSocket 消息格式

**客户端 → 服务端：**

```json
{
  "type": "message",
  "chat_id": "xxx",
  "content": "hello"
}
```

**服务端 → 客户端：**

```json
{
  "type": "message",
  "chat_id": "xxx",
  "from_user_id": "yyy",
  "content": "hello",
  "timestamp": 1716700000
}
```

## 七、关键决策记录

| 日期 | 决策 | 原因 |
|------|------|------|
| 2026-05-25 | 移动端用原生技术（Kotlin/Swift） | 性能最优，与桌面端技术栈解耦 |
| 2026-05-25 | 桌面端用六边形架构 | 业务逻辑与框架解耦，便于测试和替换 |
| 2026-05-25 | P0 优先聊天核心，跳过 IDE 功能 | 快速验证核心价值 |
| 2026-05-26 | AppMode 枚举：`finance \| software \| general` | 三值互斥，统一管理 |
| 2026-05-26 | Android 用 Retrofit 做网络 | 成熟稳定，与 Compose 配合良好 |
| 2026-05-26 | iOS 用 URLSession + async-await | 现代 Swift 并发，原生方案 |
