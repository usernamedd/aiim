# 需求文档 - 后端（AI 即时通讯服务器）

> 项目：AIIM - AI-Native Instant Messenger
> 版本：v2.0（AI-Native 重构版）
> 状态：进行中

---

## L1 自然语言需求

我们需要构建一个 **AI-Native 的即时通讯平台**，AI 不是附加功能，而是平台的核心能力。

在这个平台上，各行各业的用户（软件工程师、金融从业者、医护人员等）都可以拥有专属的 **AI 智能体（Agent）**，这个 Agent 可以：
- 帮用户**整理和润色**要发出的消息（富文本格式，支持标题/列表/表格/代码块）
- 帮用户**生成回复建议**，用户可一键发送或修改后再发
- 接收用户的**多模态输入**（语音/图片/文件），自动处理后发送
- 根据用户设置的**命令和参数**，自动执行消息排队、定时发送、批量发送
- 主动**推送信息**给用户（如行情预警、患者提醒、工单状态）
- 用户也可以**自己创建**新 Agent（无代码拖拽 或 代码开发）

四端全做：Android + iOS + 桌面端 + 后端服务器。

## L3 功能需求（AI-Native 版）

### 3.1 账号与认证

| 编号 | 功能 | 说明 |
|------|------|------|
| F1.1 | 用户注册 | 邮箱 + 密码，支持 JWT 认证 |
| F1.2 | 用户登录 | 返回 access_token（15min）+ refresh_token（7天） |
| F1.3 | 刷新 Token | 用 refresh_token 换取新 access_token |
| F1.4 | 登出 | 使 refresh_token 失效 |
| F1.5 | Agent 授权 | 用户给 Agent 授权访问自己的数据 |

### 3.2 即时消息（基础）

| 编号 | 功能 | 说明 |
|------|------|------|
| F2.1 | 建立 WebSocket 连接 | 认证后维持长连接，支持心跳 |
| F2.2 | 发送私聊消息 | 点对点消息，实时投递 |
| F2.3 | 发送群聊消息 | 推送到群内所有在线成员 |
| F2.4 | 消息确认（ACK） | 接收方确认收到，发送方显示已读状态 |
| F2.5 | 消息重发 | 发送失败时自动重试（指数退避） |
| F2.6 | 离线消息缓存 | 用户离线时缓存消息，上线后推送 |

### 3.3 AI 智能体（Agent）管理

| 编号 | 功能 | 说明 |
|------|------|------|
| F3.1 | **预置 Agent 列表** | 平台预置的垂直行业 Agent，用户可直接订阅 |
| F3.2 | **订阅 Agent** | 用户订阅 Agent，建立与 Agent 的对话通道 |

### 3.4 AI 消息处理

| 编号 | 功能 | 说明 |
|------|------|------|

| F4.9 | **消息翻译** | AI 翻译对话内容（中↔英↔日 等） |

```json
// 客户端 → 服务器：发送消息

}
```

### 4.4 技术实现要求

| 项目 | 要求 |
|------|------|
| WebSocket 心跳 | 客户端每 15 秒发送 Ping，服务器 60 秒无响应则断开 |
| 消息持久化 | 所有消息立即写入 SQLite |
| 离线消息 | 通过 Redis 缓存（生产环境），开发环境用 SQLite |
| 并发支持 | Go goroutine + channel，支撑万人同时在线 |
| 日志 | 结构化日志（zap），包含 trace_id |
| 安全 | HTTPS 全站加密，JWT + refresh_token 轮换 |
| API 版本 | v1，后续兼容 |
