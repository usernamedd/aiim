## 各平台详细说明

### Android

| 项目 | 选择 | 理由 |
|------|------|------|
| 语言 | Kotlin | Android 官方首选，与 Java 100% 互操作 |
| UI 框架 | Jetpack Compose | Google 主推，声明式，代码量比 XML 少 50% |
| 设计语言 | Material 3 | Google 统一设计规范 |
| 状态管理 | ViewModel + StateFlow | 官方推荐，生命周期感知 |
| 本地数据库 | SQLite (Room) | 轻量、可靠、异步支持好 |
| 网络 | Retrofit + OkHttp | Android 生态最成熟 |
| WebSocket | OkHttp WebSocket | 与 Retrofit 同源，一致性好 |
| 富文本编辑 | 基于 Markdown 设计，可视化编辑器组件 | **新增：AI 生成内容需要富文本呈现** |
| 语音输入 | Android 原生 SpeechRecognizer 或 第三方 | 语音转文字后交给 AI 处理 |

### iOS

| 项目 | 选择 | 理由 |
|------|------|------|
| 语言 | Swift | Apple 主推，现代、安全、性能好 |
| UI 框架 | SwiftUI | Apple 主推声明式 UI，2024 年已成熟 |
| 设计语言 | Apple Human Interface Guidelines | Apple 官方规范 |
| 状态管理 | @Observable | SwiftUI 内置，轻量直观 |
| 本地数据库 | SQLite | 轻量、符合 Apple 隐私优先理念 |
| 网络 | URLSession | Apple 原生，无需引入第三方 |
| WebSocket | URLSession WebSocketTask | Apple 原生支持 |
| 富文本编辑 | TextKit 2 或原生 AttributedString | **新增：支持 Markdown 渲染 + 可视化编辑** |
| 语音输入 | Speech 框架 | Apple 原生语音识别 |

### 桌面端

| 项目 | 选择 | 理由 |
|------|------|------|
| 语言 | TypeScript | 类型安全、生态丰富、前端团队熟悉 |
| 框架 | Tauri | 性能比 Electron 高 5-10x，内存占用小 |
| UI 框架 | React | 生态最完善，组件复用率高 |
| 样式 | CSS | 灵活、可实现炫酷效果（动画/毛玻璃等） |
| 状态管理 | Zustand | 轻量（无 boilerplate）、支持 Redux DevTools |
| 本地数据库 | SQLite | 与移动端、后端一致，零学习成本 |
| WebSocket | 原生 WebSocket API | 浏览器原生，无需库 |
| 富文本编辑 | React-Markdown + 自定义编辑器组件 | **新增：参考 Typora/Notion 的富文本编辑体验** |
| 命令补全 | 自研命令解析器（参考 Telegram Bot 命令） | **新增：斜杠命令系统** |

### 后端

| 项目 | 选择 | 理由 |
|------|------|------|
| 语言 | Go | 高性能、并发友好、学习曲线平缓 |
| HTTP 框架 | Gin | 轻量、路由性能极佳、中间件丰富 |
| ORM | GORM | Go 最流行的 ORM，链式 API 设计优雅 |
| 数据库 | SQLite（开发）→ PostgreSQL（生产） | 开发零配置，生产可水平扩展 |
| WebSocket | gorilla/websocket | Go 最成熟的 WebSocket 库 |
| AI 接入层 | **AI Gateway** | 统一接入 OpenAI / Claude / 本地模型，智能路由 |
| 认证 | JWT | 无状态、可跨端、业界标准 |
| 密码存储 | bcrypt | 业界标准，彩虹表防护 |
| 日志 | zap | Uber 开源，高性能结构化日志 |
| **消息队列** | Redis Stream 或内部队列 | **新增：定时发送/延迟发送/条件触发** |
| **Agent 运行时** | 沙箱隔离（gVisor/Firecracker） | **新增：用户自定义 Agent 代码安全执行** |

## 通用组件选型

### 实时通讯

| 组件 | 技术 | 说明 |
|------|------|------|
| 协议 | WebSocket | 全双工，延迟低 |
| 消息格式 | JSON | 简单直观，便于调试 |
| 心跳 | Ping/Pong | 15秒间隔，维持连接 |
| 重连 | 指数退避 | 断线自动重连 |

### 认证

| 组件 | 技术 | 说明 |
|------|------|------|
| Token | JWT | access_token（短期）+ refresh_token（长期） |
| 签名算法 | RS256 | 非对称，防伪造 |
| 过期时间 | access: 15min / refresh: 7 days | 安全与体验平衡 |

### 数据库设计原则

- **SQLite 优先**：所有端统一 SQLite，降低复杂度
- **PostgreSQL 迁移**：生产环境通过 GORM 自动迁移，无需手动改 SQL
- **表结构规范**：每个表必须有 `id`(自增)、`created_at`、`updated_at`

## 技术选型决策记录

| 日期 | 决策 | 原因 |
|------|------|------|
| 2026-05-23 | 桌面端弃用 C++/Win32，改用 Tauri | Win32 炫酷效果差，开发体验不佳 |
| 2026-05-23 | 后端弃用 Node.js，改用 Go | 用户要求，性能优先 |
| 2026-05-23 | 数据库统一 SQLite → PostgreSQL | 开发简单，生产可水平扩展 |
| 2026-05-23 | 桌面端使用 Tauri + React + Zustand | 性能、开发体验、炫酷效果兼顾 |
